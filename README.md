# Поиск объявлений по текстовому запросу

Репозиторий создан в качестве отчета к тестовому заданию для Avito DS Bootcamp по направлениию NLP&LLM. Задача состоит в кандидатогенерации объявлений по запросам пользователя. В качестве стартового бейзлайнов были выбраны BM25 и TF-IDF на запросе или infm против одного из текстовых полей в item. Где TF-IDF показал себя гораздо хуже и был сразу отброшен.

Помимо этого для базщового скоринга были рассмотрены языковые модели `bge-m3, giga-embeddings`, но на них получали эмбеддинги только с запроса и щаголовка item, на остальных полях долго прогонять. Финальная модель + лучший скор дает кандидатогенерация несколькими dense и sparse моделями, последующее объединение кандидатов и рескоринг по точному совпадению локаций или haversine distance между точками объявлений и оценочными центроидами локаций запросов.

Все методы кандидатогенерации реализованы поверх базового класса.

По данным стоит отметить наличие `infm_params_text`, которые наверное можно распарсить в иерархическую структуру, стоит отметить как идею на будущее. В моменте был неочевидный риск и показалось, что зависимость между двумя такими соответствующими полями сможет отоловить BM25. 

Для валидации моделей был написани модуль воспроизводимого сплита данных по запросам и без утечек.

В целом инфу по реализации можно вытягивать с приведенных ниже модудей и ноутбуков, но лучше не знкаомитться с `src/retrieval_comparison.py`, это что-то иное.

Снизу оставил таблицы, полученны в ходе впыолнения работы, там в основном значения метрики в разных экспериментах.

Финальный ноутбук с валидацией, прогоном на тесте, бенчмаркинигом можно найти на Kaggle: [ссылка](https://www.kaggle.com/code/mihailchirkov/avito-ds-bootcamp-fin)

## Классы

[retriever.py](src/retriever.py) -- базовый класс для всех моделей кандидатогенерации с основными методами `fit, retrieve, score_candidates`

[bm25.py](src/retrievers/bm25.py) -- класс, реализующий кандидатогенерацию с помощью bm25 по текстовому полю запроса и объявления, опциональная лемматизация

[tfidf.py](src/retrievers/tfidf.py) -- класс, реализующий кандидатогенерацию с помощью bm25 по текстовому полю запроса и объявления, опциональная лемматизация, альтернатива n-грамм по словам и символам

[dense.py](src/retrievers/dense.py) -- класс, реализующий кандидатогенерацию на dense векторах с языковых моделей (здесь выбраны `bge-m3, giga-embeddings-480M-Instruct`), с KNN основанном на FAISS (потенциально можно поменять на ANN)

[hybrid.py](src/retrievers/hybrid.py) -- класс, реализующий кандидатогенерацию комбинацией моделей, например (bm25 запрос-заголовок, bm25 запрос-описание, giga запрос-заголовок), сначала генерим кандидатов каждой моделью, затем объединяем множества, а потом ранжируем по haversine distance до локации, координаты локации при этом считаем как медиану по широте и долготе среди объявлений с одной локацией, если локация встречалась только в запросах, то есть фоллбэк с медианой по запросам

[geo_first.py](src/retrievers/geo_first.py) -- класс, реализующий кандидатогенерацию похожим образом на прошлый, но в обратном порядке, сначала берем топ близких кандидатов, потом скорим их набором моделей и сортируем по кортежу скоров, порядок в кортеже выбираем сами

[scorer.py](src/scorer.py) -- легаси код, сначала была идея строить интерфейс через PairScorer, но был ваыбран путь более удобный для retrieval задач

[retrieval_comparison.py](src/retrieval_comparison.py) -- святой вайбкод, за это дико извиняюсь, хотел просто меньше кода в финальному ноутбуке оставить, но кодекс воспринял это по-своему))) я постарлся поправить форматирование, разделить на блоки, но как по мне код все еще плохо читаем, но вся его суть это лаконичный интерфейс ноутбука под загрузку, сплит, валидацию, тестирование, прогон бенчмаркинга избранных моделей (`geo_first.py`, `hybrid.py`)

[geo.py](src/geo.py) -- реализация haversine distance и подсчета центроид локаций с группировкой на item или с фоллбэком на query при новых location_id

[split.py](src/split.py) -- реализация воспроизводимого сплита по запросам.

### BM25 и географические сигналы

| Вариант | Recall@50 val | Recall@50 test | Настройки |
|---|---:|---:|---|

| Совпадение локации | 0.3120 | 0.3002 | N=3000, α=0.2 |
| Расстояние | 0.3120 | 0.3013 | N=3000, β=0.2, τ=100 км |
| Совпадение локации + расстояние | 0.4161 | 0.4327 | N=3000, α=β=0.2, τ=100 км |

### BM25 и TF-IDF

Recall@10 на тестовых контекстах. BM25 — значения из [BM25_pipeline.ipynb](notebooks/BM25_pipeline.ipynb); TF-IDF сравнивался на тех же контекстах с ограничением словаря в 20 000 признаков и усечением текста объявления до 100 символов.

| Вход | BM25 | TF-IDF, слова | TF-IDF, char_wb |
|---|---:|---:|---:|
